# Архитектура и план развития

## Принятые решения

| Вопрос | Решение |
|---|---|
| Root | Не нужен. Root — опция, которую можно включить в любой момент (chroot вместо proot). |
| Распространение | GitHub / F-Droid, не Google Play. |
| Лицензия | GPLv3. Модули терминала из Termux — Apache 2.0; proot — GPL v2+; talloc — LGPL v3+. |
| Целевое железо | Snapdragon (Adreno) — ради GPU-ускорения через Turnip. Остальные — программный рендер. |
| Финальная цель | Полная оптимизация под Samsung DeX. |

## Слои

```
┌──────────────── Android-приложение (Kotlin) ─────────────────┐
│  Рабочий стол: обои, значки, панель задач, меню «Пуск»       │
│  Оконный менеджер (DesktopArea / DesktopWindow)              │
│  Нативные окна: терминалы, установщик Linux, «О программе»   │
│  Linux-окна ← Wayland-композитор (C/C++, NDK)        [этап 3]│
└───────────────────────────────┬──────────────────────────────┘
                                │ pty, позже Unix-сокеты
┌──────── Debian 13 arm64 через proot (libproot.so) ───────────┐
│  apt, bash, консольные программы                    [этап 2] │
│  GTK/Qt-приложения, Xwayland                     [этапы 3–4] │
│  PulseAudio → AAudio, Mesa Zink/Turnip → GPU        [этап 5] │
└──────────────────────────────────────────────────────────────┘
```

## Код

- `app/` — оболочка.
  - `wm/` — оконный менеджер. Окна — обычные View, порядок детей = z-order.
    Любое содержимое окна реализует `WindowContent`.
  - `shell/` — панель задач, значки, системные окна.
  - `term/` — терминал: `ShellSpec` (что запускать), `TermSessions` (сессии живут дольше
    Activity), `TerminalContent` (окно), `ExtraKeysBar`.
  - `linux/` — Linux-окружение: `LinuxInstaller` (Docker Hub → проверка sha256 → распаковка),
    `DockerRegistry`, `TarExtractor`, `LinuxEnv` (команда proot), `ProcFakes`, `LinuxSetupContent`.
  - `service/SessionService` — foreground service, держит процессы живыми в фоне.
- `native/proot/` — исходники termux/proot (GPL v2+), `native/talloc/` — talloc (LGPL v3+).
- `buildSrc/BuildProotTask.kt` — сборка proot и загрузчика чистым clang из NDK (без make/waf),
  результат кладётся в APK как `libproot.so` / `libproot-loader.so`.
- `terminal-emulator/`, `terminal-view/` — библиотеки Termux (Apache 2.0), изменения помечены в шапке файла.

## Этапы

### 1. Рабочий стол и терминал — готово
Окна (перемещение, размер, свернуть/развернуть, прилипание к краям), панель задач,
меню «Пуск», терминал Android с доп. клавишами, мышь и горячие клавиши.

Проверено в беспроводном DeX (2026-11-24): окна плавающие, рамки и курсоры мыши, прилипание
к краям, правый клик, колесо, переподключение DeX без перезапуска Activity, фокус клавиатуры
следует за активным окном.

Оболочка на телефоне (2026-11-24): эксклюзивный полный экран (строка состояния и навигация
Android скрыты, свайп от края показывает их на время), только альбомная ориентация
(`sensorLandscape`), рисование под вырезом камеры. Вместо строки состояния — область справа на
панели задач: VPN, точка доступа, Wi-Fi / Ethernet, тип сети (5G/LTE…) и уровень сигнала,
режим полёта, батарея (заряд, зарядка), время и дата. Нажатие открывает панель «Интернет»,
настройки батареи или календарь. Разрешения: только `ACCESS_NETWORK_STATE` (обычное);
тип сети берётся из `TelephonyDisplayInfo` без `READ_PHONE_STATE`. Всплывающие меню и диалоги
сами снова прячут системные панели.

Масштаб интерфейса (Настройки → «Масштаб интерфейса», 50–130 %, отдельно для экрана телефона и
для DeX / монитора): переопределяется `densityDpi` Activity (`UiScale`), поэтому вместе
масштабируются все dp и sp оболочки — окна, панель задач, текст терминала. Применение
пересоздаёт Activity; терминалы и окна Linux переживают это, окно настроек открывается снова.
У S24 Ultra системная плотность ≈ 3,75 (596 dpi): при 100 % рабочий стол всего 838 × 387
точек, при 70 % — 1197 × 553. Linux-программы получают ближайший целый масштаб Wayland
(×2 при 50–70 %, ×3 при 80 % и выше), `wl_output` рассылается заново.

DeX (беспроводной DeX на ПК, 1600 × 900, 150 dpi; 2026-11-24): HandTop открывается окном DeX;
полный экран — системной кнопкой ⛶ в заголовке окна DeX: панель задач и заголовок DeX
исчезают, остаётся только рабочий стол HandTop со своей панелью. Программно это сделать
нельзя: `requestFullscreenMode` DeX отклоняет («Not allow change to fullscreen windowing on
desktop windowing»). Масштаб DeX хранится отдельно (100 % = 1707 × 960 точек, проверено 130 %);
при смене размера окна `wl_output` получает новый размер.

Уведомления (2026-11-24): `NotificationListenerService` (`service/NotificationsService`,
`notify/`). На панели задач — значки последних трёх приложений и колокольчик со счётчиком;
по нажатию — центр уведомлений над панелью: карточки (значок приложения в цвете уведомления,
имя приложения, время, заголовок, текст), нажатие открывает уведомление на том же экране
(`ActivityOptions.launchDisplayId`, разрешение запуска из PendingIntent для Android 14+), ✕ —
закрыть, «Очистить все». Доступ включает пользователь («Доступ к уведомлениям»); без него
центр объясняет, как включить, и подсказывает про «Ограниченную настройку» у APK не из
магазина. Имена и значки приложений — через `<queries>` с `MAIN` (как у лаунчера).
Проверено в DeX: значки, счётчик, список, закрытие ✕, открытие уведомления (AdGuard открылся
окном на экране DeX). «Очистить все» на устройстве не нажималась — это стёрло бы настоящие
уведомления пользователя.

### 2. Linux-окружение — основное готово
Проверено на S24 Ultra, Android 17, targetSdk 37 (2026-11-24):
- установщик: официальный `debian:trixie-slim` (arm64) с Docker Hub, проверка sha256,
  распаковка ≈ 108 МБ за несколько секунд;
- «Терминал Linux»: bash под proot с фейковым root, `apt update` / `apt install` работают
  (fastfetch, htop), часовой пояс берётся из Android;
- недоступные приложению файлы `/proc` (stat, uptime, loadavg, version…) подменяются;
- foreground service: сессия пережила 30 с в фоне.

Хвосты этапа 2 (0.2.0, проверено на устройстве 2026-11-24):
- выбор дистрибутива: Debian 13, Ubuntu 26.04 LTS (образ из 2 слоёв, OCI whiteouts),
  Alpine (нет bash → `/bin/sh -l`, нет tzdata → POSIX-смещение TZ), Fedora 45 (dnf5);
- переустановка атомарна: новая система распаковывается в `rootfs.new` и заменяет старую
  только целиком — неудачная установка ничего не ломает; удаление с подтверждением;
- окно «Настройки»: доступ к памяти телефона (`MANAGE_EXTERNAL_STORAGE` → `/sdcard` и `/storage`
  в Linux, чтение и запись проверены), состояние phantom process killer (Android 14+ читается
  из `Settings.Global`) и кнопка в параметры разработчика, управление Linux;
- имя хоста `handtop` (через `--kernel-release` proot), `TERM_PROGRAM=HandTop`;
- заголовок окна берётся из терминала (Ubuntu/Fedora выставляют `root@handtop: ~`).

Осталось:
- **режим root (chroot)** — нужен телефон с root: после chroot файлы rootfs принадлежат uid
  приложения, а не root (apt/`_apt` могут упереться в права), режимы proot и chroot не должны
  делить один rootfs без смены владельца.

### 3. Свой Wayland-композитор — первые окна работают
Протокол реализован на Kotlin (`app/.../wayland/`), в C (`app/src/main/cpp/handtop.c`) — только
сокеты с передачей fd, mmap общей памяти и копирование пикселей (BGRA → RGBA). libwayland и
libffi собирать не пришлось. Сокет: `rootfs/tmp/.handtop-runtime/wayland-0`
(в Linux: `XDG_RUNTIME_DIR=/tmp/.handtop-runtime`, `WAYLAND_DISPLAY=wayland-0`).

Реализовано: wl_compositor 4, wl_shm (ARGB/XRGB8888), wl_output 3 (масштаб = плотность экрана,
на S24 Ultra 3), wl_seat 5 (мышь, клавиатура с XKB-раскладкой us из `assets/`), xdg_wm_base 3
(окна, всплывающие меню, диалоги), zxdg_decoration, wl_subcompositor (подповерхности),
wl_data_device_manager 3 (буфер обмена). Каждое окно Linux = отдельный `DesktopWindow`,
закрытие окна — просьба программе (`xdg_toplevel.close`).

Рамки: программы, договорившиеся через xdg-decoration, получают наш заголовок; остальные
(GTK, weston) рисуют свой (CSD) — наш заголовок прячется, остаётся тонкая рамка для изменения
размера. Их кнопки и перетаскивание за заголовок работают через `xdg_toplevel.move/resize/
set_maximized/set_minimized`; Alt + перетаскивание двигает любое окно Linux. Диалоги
(`set_parent`, фиксированный размер min = max) открываются по центру над родителем, не
разворачиваются и не меняют размер, на телефоне тоже остаются плавающими.

Проверено 2026-11-24: `wayland-info`, `weston-simple-shm` (анимация 120 к/с без рывков),
`weston-terminal` (чёткий текст в масштабе 3, ввод с клавиатуры с Shift). Mousepad (GTK 3,
`apt install mousepad`): один заголовок, меню File/Help, ввод текста, свои кнопки
свернуть/развернуть/закрыть, перетаскивание за заголовок, диалог «Сохранить изменения?»
по центру над окном, окно открытия файла.

Известное:
- окно выбора файла GTK не сжимается уже ≈ 480 логических пикселей: в портретной ориентации
  телефона обрезалось; в альбомной (1040 × 432 логических) помещается целиком;
- масштаб Wayland только целый: при 70 % оболочка ≈ 2,6, а Linux-программы ×2 (чуть мельче);
  дробный масштаб (wp_fractional_scale_v1 / wp_viewporter) — позже;
- свайп, начатый у самой кромки экрана, забирает система (`ACTION_CANCEL` с `FLAG_CANCELED`) —
  касается любых окон, не только Linux.

Скорость (2026-11-24, шаг 2): содержимое поверхности хранится в `AHardwareBuffer`
(`wayland/Frames.kt`), который UI рисует как аппаратный `Bitmap` — без загрузки в видеопамять;
каждый коммит копирует только damage (`wl_surface.damage` / `damage_buffer`) с перестановкой
каналов. Три буфера по очереди, у каждого — damage с момента его прошлой записи (buffer age).
На Qualcomm буфер отображается в память один раз на всю жизнь: lock/unlock на каждый кадр
стоил ~0,3 мс (gralloc чистит кэш всего буфера на unlock), на других GPU — lock только
изменённой области. Android 9 и ниже — прежнее полное копирование в программный `Bitmap`.
Замер в DeX, `weston-simple-damage` 1200×700 (за кадр меняется мяч, 882 пикселя), 60 к/с:

| путь | копирование на коммит | процесс HandTop |
|---|---|---|
| было: полная копия в `Bitmap` + полная загрузка в GPU | ~535 мкс | ~22–23 % ядра |
| `AHardwareBuffer`, lock/unlock на кадр | ~320 мкс | ~19 % |
| `AHardwareBuffer`, постоянное отображение | ~27 мкс | ~17–18 % |

Оставшиеся ~17 % — цена 60 перерисовок окна Android в секунду (главный поток ~9 %,
RenderThread ~7 %), а не пиксели. Выигрыш растёт с размером окна: копирование теперь зависит
от изменённой области, а не от размера буфера.

GTK/Qt-приложения (2026-11-24, шаг 3):
- меню и прочие xdg_popup рисует `PopupLayer` поверх всех окон — меню выходят за край своего
  окна; `xdg_positioner` constraint adjustment (flip / slide / resize) по границам рабочего
  стола; `xdg_popup.grab` отдаёт меню клавиатуру (стрелки, Escape); меню закрываются, когда
  окно теряет фокус;
- буфер обмена (`Clipboard.kt`): Linux → Android (текст читается через pipe при
  `set_selection`), Android → Linux (буфер Android читается только при вставке — Android 12+
  показывает уведомление о каждом чтении), Linux → Linux (pipe вставляющего передаётся
  копирующему напрямую);
- `wl_keyboard.modifiers` отправляется до клавиши: Ctrl+A / Ctrl+C раньше приходили как «a» / «c»;
- курсоры программ (`wl_pointer.set_cursor`) → `PointerIcon` Android; `PopupLayer` (на весь
  рабочий стол) передаёт запрос формы указателя окнам под собой — `ViewGroup` спрашивает только
  верхнего ребёнка. Проверено мышью в DeX (2026-11-24): стрелки на краях окон, I-курсор в тексте;
- подповерхности: стек с `place_above/below`, позиция применяется с коммитом родителя,
  отрисовка и попадание указателя по дереву поверхностей. Упрощение: синхронная подповерхность
  показывает новое содержимое сразу, а не с коммитом родителя.
Проверено в DeX: Mousepad (меню длиннее окна, вложенное меню, меню у края экрана, копирование
в Android и обратно), weston-terminal (вставка из Mousepad), `weston-subsurfaces --no-triangle`.

Клавиатура и переходы (2026-11-24, шаг 4):
- `zwp_text_input_v3` (`TextInput.kt`): окно Linux — текстовый редактор для Android
  (`WaylandInputConnection`); текст и набираемое слово клавиатуры уходят программе как
  `commit_string` / `preedit_string` — любой язык (проверено: русский, армянский); тип поля
  (пароль, цифры, e-mail, URL…) выбирает раскладку;
- без text-input (weston-terminal) — текст как клавиши раскладки US (латиница);
- физическая клавиатура: символы вне латиницы (русская раскладка Android) — тоже как текст;
- клавиатура выезжает сама, когда программа включает ввод (фокус в поле) и физической
  клавиатуры нет, и по касанию поля пальцем; прячется, когда ввод выключен;
- переход DeX → телефон с открытыми окнами Linux: Activity перестраивается под масштаб
  телефона, `wl_output` → ×2, Mousepad и терминалы остаются открытыми.

Меню приложений (2026-11-24): окно «Приложения Linux» (значок на рабочем столе и пункт меню
«Пуск») читает `.desktop` из дистрибутива (`LinuxApps.kt`: локализованное имя, `Exec` без
`%f/%U`, иконки PNG из `hicolor` / `pixmaps`, символьные ссылки — внутри rootfs), поиск по имени,
описанию и ключевым словам. Программы запускаются без терминала (`LinuxEnv.commandSpec`,
вывод — в `/tmp/handtop-apps.log`) и держат foreground service, как терминалы;
`Terminal=true` — в окне терминала. Окно Wayland получает иконку своей программы по `app_id`
(заголовок и панель задач). Иконки SVG пока не показываются (нужен растеризатор).

Звук (2026-11-24): PulseAudio внутри Linux с `module-pipe-sink` пишет смешанный поток
(48 кГц, s16le, стерео) в FIFO `/tmp/.handtop-runtime/handtop-audio`; `SoundBridge` читает его
(`poll()` + неблокирующее чтение) и играет через `AudioTrack`. Конфигурация — `/etc/handtop/pulse.pa`,
сокет — `$XDG_RUNTIME_DIR/pulse/native`, ALSA-программы идут через плагин pulse
(`/etc/asound.conf`, если его нет). PulseAudio стартует вместе с терминалом или приложением Linux;
простаивающий приёмник засыпает через 3 с, `AudioTrack` ставится на паузу через 1 с без данных —
вывод Android может уснуть. Настройки → «Звук»: статус и кнопка установки (apt/apk/dnf в окне
терминала). Проверено: `speaker-test` 3 с → 163456 кадров (≈3,4 с) проиграно, затем плеер Android
`paused`. Задержка — до ~0,35 с (буфер канала 64 КБ): для видео и игр позже — синхронизация.

X11 (2026-11-24): rootless Xwayland (`:0`, `-shm -nolisten tcp -nolisten local`) запускается с
сессией Linux, если установлен; `DISPLAY=:0` во всех процессах Linux. HandTop — оконный менеджер X11
(`Xwm.kt`, свой минимальный клиент протокола X в `X11.kt` через unix-сокет): Composite
`RedirectSubwindows(Manual)` (без этого rootless Xwayland не создаёт `wl_surface` окнам),
MapRequest/ConfigureRequest, `WM_STATE`, EWMH (`_NET_SUPPORTING_WM_CHECK`, `_NET_ACTIVE_WINDOW`,
`_NET_WM_STATE`, `_NET_WM_MOVERESIZE`, `WM_CHANGE_STATE`), заголовки (`_NET_WM_NAME`/`WM_NAME`),
`WM_CLASS` → иконка, `WM_TRANSIENT_FOR` → диалоги, `WM_NORMAL_HINTS` → фиксированный размер,
`_MOTIF_WM_HINTS` → без рамки, закрытие через `WM_DELETE_WINDOW` (иначе `KillClient`), фокус
`SetInputFocus` + `WM_TAKE_FOCUS`. Связь X-окно ↔ `wl_surface`: `xwayland_shell_v1` (serial) или
старый `WL_SURFACE_ID`. Общий интерфейс `Toplevel`/`Popup`: X-окна идут через тот же
`WaylandWindowContent`, панель задач и `PopupLayer`; override-redirect окна (меню, подсказки) —
попапы активного X-окна; координаты X = логические пиксели рабочего стола, позиция окна
сообщается X при каждом перемещении. `zxdg_output_manager_v1` даёт Xwayland логический размер
экрана (корень 1560×720). Настройки → «Программы X11»: статус и установка (apt/apk/dnf).
Проверено: xclock, xedit (ввод с клавиатуры, закрытие ✕), bitmap (меню File точно под кнопкой,
в том числе после перемещения окна), Mousepad (Wayland) работает как прежде.
Пока нет: буфер обмена X11 ↔ Android, изменение размера окна по запросу программы
(ConfigureRequest после показа отклоняется), HiDPI для X11 (1 пиксель X = scale пикселей экрана,
шрифты крупные и мягкие), закрытие X-меню кликом вне окна проверено только логикой.

D-Bus и мультимедиа (2026-11-24): сессионная шина D-Bus — часть сессии (`SessionBus.kt`):
`dbus-daemon` на `$XDG_RUNTIME_DIR/bus`, `DBUS_SESSION_BUS_ADDRESS` во всех процессах, службы
запускаются по требованию (Xfconf, dconf, уведомления). В proot EXTERNAL-аутентификация не
проходит (proot подделывает uid 0, ядро сообщает настоящий uid) — шина принимает ANONYMOUS
(сокет в каталоге 0700 внутри данных приложения). `NO_AT_BRIDGE=1`: шины специальных
возможностей нет. Проверено с `xfce4-goodies` + Parole + GStreamer (DeX): Parole играет видео со
звуком (640×360@30: Parole ~17–27% ядра, HandTop ~14–17%), развёрнутое окно масштабирует видео;
меню GTK под X11 открываются кликом и закрываются кликом мимо; диалог открытия файлов — окно над

## Риски и находки

1. **Запуск бинарников (W^X) — решено.** С targetSdk ≥ 29 Android запрещает `execve()` файлов
   из каталога данных приложения (`./uname` из `files/` → `Permission denied`), но разрешает
   `mmap` с PROT_EXEC (`linker64 files/.../uname` работает). Поэтому proot и загрузчик лежат в
   APK как `lib*.so` (nativeLibraryDir исполняем), а Linux-программы грузит загрузчик proot.
   proot собран с `PROOT_UNBUNDLE_LOADER`: загрузчик не распаковывается в app data.
2. **Android закрывает приложениям часть системы.** `/system/bin/sh` можно запустить, но нельзя
   прочитать (поэтому proot не может его загрузить — для Linux не важно); листинг `/system/bin`
   и `/data` запрещён; `/proc/stat`, `/proc/uptime` и др. закрыты — подменяются (`ProcFakes`).
3. **Phantom process killer (Android 12+).** Убивает лишние дочерние процессы (лимит 32 на все
   приложения). Android 14+: «Отключить ограничения дочерних процессов» в настройках разработчика;
   12–13: `adb shell device_config put activity_manager max_phantom_processes 2147483647`.
4. **proot создаёт точки монтирования с правами 000** (`rootfs/storage`, `rootfs/sdcard`):
   удаление rootfs обязано сначала выдать себе права на каталог (`FileTrees.delete`).
5. **Отладка proot на устройстве** однажды повесила телефон (вместе с беспроводным DeX и scrcpy):
   эксперименты с нативным кодом — по одному и с `timeout`.
6. **Дисплейный сервер** — самая трудоёмкая часть; делать маленькими шагами.
7. **Переопределение плотности и `recreate()`.** После пересоздания Activity её базовый контекст
   (`baseContext`) начинает возвращать уже уменьшенную плотность — ресурсы делят токен Activity.
   Настоящую плотность экрана брать только через `createDisplayContext()` приложения
   (`UiScale.systemDpi`).
8. **DeX.** У окна DeX `isInMultiWindowMode` = false; признак DeX — дисплей не 0
   (`UiScale.isDesktop`).
