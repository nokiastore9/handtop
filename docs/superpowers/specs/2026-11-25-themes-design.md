# Темы оформления: механизм тем и классическая тема

Дата: 2026-11-25. Статус: на согласовании. Прошёл проверку «глазами исполнителя»; её три вопроса решены
ниже (помечены «решение проектировщика»).

## Зачем

Пользователь хочет переключать внешний вид HandTop между несколькими темами. Первая новая
тема — **классическая**, в духе классической темы Windows 7 (как Windows 2000 / 98):
упрощённые серые окна без Aero, без прозрачности и без анимаций. Позже придут другие темы
(в духе GNOME, XP и т. д.), каждая отдельным шагом. Механизм, который делается сейчас,
должен их выдержать без переделки.

Тема делается «в духе»: своя графика и свои значки, без логотипов, картинок и шрифтов
Microsoft и без слова «Windows» в интерфейсе.

Макеты, по которым договорились: https://claude.ai/artifact/9Y7dgfsZSaZccC4Ubjrw4A (вариант Б).

## Цели

1. Механизм тем: тема — это не только цвета, но и способ рисовать рамку окна, кнопки,
   списки, поля, меню, панель задач, а также включены ли анимации, размытие, тени.
2. Две темы:
   - **Современная** — нынешний тёмный вид HandTop, без изменений. Тема по умолчанию.
   - **Классическая** — описана ниже.
3. Классическая тема меняет **всё, что рисует HandTop** (решение пользователя, вариант Б):
   рамки окон, панель задач, «Пуск», меню, всплывающие окна, а также содержимое
   собственных окон HandTop — Настройки, Файлы, Лаунчпад, Обои, О программе, установка
   Linux, центр уведомлений, календарь, полоса доп. клавиш терминала, диалоги.
4. Переключатель: Настройки → Рабочий стол → «Тема» (два варианта). Применяется сразу.
   Выбор сохраняется. Терминалы, Linux-программы и их окна при смене темы не закрываются.

## Не цели (сейчас)

- Вид **внутри** Linux-программ (кнопки и меню GTK/Qt). Рамки и заголовки их окон рисует
  HandTop, поэтому они станут классическими сами; содержимое — нет. Включать
  классическую тему GTK/Qt внутри Linux — следующий отдельный шаг (решение пользователя).
- Другие темы (GNOME, XP и т. д.).
- Перенос панели задач или изменение расположения элементов: классическая тема меняет
  только вид.
- Цвета самих терминалов (чёрный фон и палитра терминала остаются как есть).
- Linux-программы, которые рисуют заголовок окна сами (GTK 4/libadwaita, программы GTK 3
  с «header bar», часть программ X11), сохраняют свой заголовок: HandTop рисует рамку
  только тем программам, которые это разрешают (xdg-decoration). Это часть «вида
  внутри Linux-программ» и уходит в следующий шаг вместе с темами GTK/Qt.
  *(Решение исполнителя-проектировщика, по вопросу проверки.)*

## Анти-цели (провал, даже если «работает»)

- Любые логотипы, значки, картинки, шрифты Microsoft или их перерисовка один в один.
- Половинчатая тема: где-то в HandTop остался тёмный «современный» экран или элемент.
- Неудобство пальцем: мелкие кнопки «как в 98-м» на телефоне. Размеры элементов
  остаются сенсорными (как сейчас), меняется только рисунок.
- Потеря открытых терминалов, Linux-программ или идущей работы (копирование файлов,
  установка Linux) при смене темы.

## Ограничения

- Android 8.0+ (minSdk 26). Размытие (RenderEffect) есть только с Android 12; в
  классической теме оно не используется вовсе.
- Работает на телефоне и в DeX/на мониторе, пальцем и мышью; при любом масштабе
  интерфейса (50–150 %).
- Интерфейс HandTop собран в коде, без XML-разметки. Цвета сейчас в `ui/Ui.kt`
  (`Palette`, ~24 цвета, 17 файлов), ещё ~30 цветов зашиты прямо в код разных экранов.
- Для всех устройств, не только Samsung.

## Подходы

1. **Тема как объект в коде + пересоздание экрана при смене — выбран.** `Palette`
   превращается в тему; общие элементы интерфейса (кнопка, строка списка, поле, выбор
   варианта, флажок, заголовок раздела, рамка группы, меню, рамка окна) создаются
   через тему. Смена темы — `recreate()` активности, как уже сделано для смены масштаба:
   сессии терминалов и Linux-окна это переживают.
2. Стандартные XML-стили Android (`Theme.HandTop.Classic` и атрибуты). Не подходит:
   разметки почти нет, все виды создаются в коде, стили пришлось бы протягивать вручную
   в каждое место — выигрыша нет.
3. Перекраска на лету без пересоздания. Не подходит: каждый элемент должен был бы сам
   следить за темой и перерисовываться — много кода ради невидимой разницы
   (пересоздание занимает доли секунды).

## Как устроено (решено)

### Тема

- Тема — объект с:
  - цветами (то, что сейчас в `Palette`, плюс цвета, зашитые в экраны);
  - способами рисовать элементы: фон рамки окна (активной/неактивной), заголовок окна,
    кнопки заголовка, фон панели задач, кнопку окна на панели (обычная / активная),
    кнопку «Пуск», область значков и часов, фон меню, выделенный пункт меню,
    разделитель, кнопку, список, выделенную строку, поле ввода, группу с подписью,
    выбор из нескольких вариантов, флажок/переключатель, полосу прогресса;
  - флагами поведения: анимации, размытие под лаунчпадом, тени (elevation),
    скругления, полупрозрачность.
- Текущая тема читается при создании активности (из настроек, ключ темы в prefs
  «settings») и действует до следующего пересоздания.
- Все экраны HandTop переходят на общие элементы из темы вместо своих приватных
  помощников (`heading()`, `body()`, `toolButton()`, ручные `GradientDrawable` и т. п.).
  Цвета, зашитые в экраны, переезжают в тему.

### Классическая тема — вид

Значения цветов (стандартная классическая палитра, сами по себе не охраняемы):

| Роль | Цвет |
|---|---|
| Поверхность (face) | `#C0C0C0` |
| Свет кромки / внутренний свет | `#FFFFFF` / `#DFDFDF` |
| Тень кромки / тёмная тень | `#808080` / `#0A0A0A` |
| Заголовок активного окна | переход `#000080` → `#1084D0` слева направо, текст белый жирный |
| Заголовок неактивного окна | переход `#808080` → `#B4B4B4`, текст `#DFDFDF` |
| Выделение (строка, пункт меню) | `#000080`, текст белый |
| Поля и списки | `#FFFFFF`, текст чёрный |
| Текст | чёрный; недоступный — серый `#808080` с белым тиснением 1 px |

Рисунок:

- **Объём** рисуется кромками в 1–2 физических пикселя (как на макете), без скруглений
  и теней: «выпуклый» (кнопки, рамки окон, панель, меню), «утопленный» (поля, списки,
  область часов), «нажатый» (нажатая кнопка, кнопка активного окна на панели — с мелкой
  шахматной штриховкой), «гравированный» (рамка группы, разделители).
- **Окно:** выпуклая рамка, заголовок с переходом, кнопки заголовка — выпуклые
  квадратики с чёрными значками (свернуть / развернуть / восстановить / закрыть),
  крупные для пальца. Высота заголовка как сейчас.
- **Панель задач:** серая, сверху светлая кромка. Слева выпуклая кнопка «Пуск» с буквой H
  и надписью «Пуск» (строка `start_menu` уже есть), кнопка лаунчпада, кнопки окон
  (активное — «нажатое»), справа значки состояния и часы в утопленной рамке.
- **«Пуск»:** выпуклое меню с вертикальной синей полосой слева, на ней «HandTop»
  снизу вверх; пункты с крупными значками; выделенный — синий.
- **Меню рабочего стола и прочие всплывающие меню:** выпуклые, выделение синее,
  недоступные пункты серые с тиснением.
- **Содержимое окон HandTop:** серый фон; списки и поля белые утопленные; разделы —
  группы с гравированной рамкой и подписью; выбор масштаба и подобные «таблетки» —
  переключатели (радиокнопки); вкл/выкл — флажки; кнопки — выпуклые.
- **Лаунчпад:** без размытия и без анимации; непрозрачная серая поверхность, поле
  поиска утопленное, подписи значков чёрные, выделение синее.
- **Центр уведомлений, календарь, диалоги** (подтверждение удаления и т. п.) — в том же
  стиле: выпуклая панель, кнопки «ОК/Отмена» выпуклые.
- **Подсказка прилипания окна к краю:** без полупрозрачной заливки, просто рамка.
- **Значки HandTop** (все `res/drawable/ic_*`, кроме значка приложения): свой набор в
  классическом духе — цветные, с лёгким объёмом, как на макете; рисуем сами. Тема
  выбирает значок: классический, если он есть, иначе обычный. Значки Linux-программ
  не меняются (они от самих программ).
- **Шрифт:** системный (как сейчас); заголовки окон жирные. Шрифты Microsoft не
  используются.
- **Обои** при смене темы не меняются. В список обоев добавляется однотонный
  бирюзовый `#008080` («Бирюзовый», доступен в любой теме).
- **Анимации:** выключены (лаунчпад, возврат значка при перетаскивании, анимации
  всплывающих окон). Тени окон и меню — нет.

### Переключение

- Настройки → Рабочий стол → раздел «Тема»: «Современная» / «Классическая».
- Выбор сохраняется и применяется сразу пересозданием активности, как при смене
  масштаба; окно Настроек открывается снова на той же странице.
- Что переживает смену темы — **ровно то же, что смену масштаба**: терминалы, окна
  Linux-программ, окно Настроек (на той же странице), тачпад. Копирование файлов и
  установка Linux продолжаются в фоне. Остальные окна HandTop (Файлы, О программе,
  Обои, установка Linux), открытые меню и лаунчпад закрываются; окна снова
  раскладываются каскадом. Сохранение каждого окна и его места — не в этом шаге: тему
  меняют редко, а прецедент со сменой масштаба уже принят.
  *(Решение проектировщика, по вопросу проверки.)*
- Строки на английском и русском: Theme / Тема, Modern / Современная,
  Classic / Классическая, Turquoise / Бирюзовый.

## Проверка

На телефоне (S24 Ultra, ×1 масштаб 100 % и ещё один масштаб) и, если получится, в DeX:

- каждый экран HandTop в обеих темах: рабочий стол, «Пуск», меню рабочего стола,
  Настройки (все разделы), Файлы (и диалоги), Лаунчпад, Обои, О программе, установка
  Linux, центр уведомлений, календарь, терминал с полосой доп. клавиш, окно
  Linux-программы (рамка), тачпад;
- нигде в классической теме не осталось тёмных «современных» элементов, скруглений,
  теней, размытия, анимаций;
- смена темы туда и обратно не закрывает терминалы и Linux-программы;
- современная тема выглядит как до изменений **на глаз**: допустимо, что при переходе на
  общие элементы чуть выровняются размеры шрифтов и отступы между экранами (сейчас у
  каждого экрана свои), но цвета, формы и расположение остаются прежними. Попиксельного
  совпадения не требуется. *(Решение проектировщика, по вопросу проверки.)*

## Оставлено на усмотрение исполнителя

- Устройство кода темы (интерфейс/класс, имена, как делятся элементы по файлам).
- Точная толщина кромок в пикселях на разных плотностях, оттенки штриховки.
- Рисунок каждого классического значка (в пределах «цветные, с лёгким объёмом, свои»).
- Как именно оформить диалоги: свой диалог в стиле темы или настроенный `AlertDialog`.
- Порядок переноса экранов на общие элементы.

## Потом (отдельными шагами)

- Классическая тема и для Linux-программ (GTK 2/3, Qt) — своя, без чужих значков;
  программы на GTK 4/libadwaita тему не меняют.
- Другие темы: в духе GNOME, XP и т. д. — каждая с макетами и согласованием.
