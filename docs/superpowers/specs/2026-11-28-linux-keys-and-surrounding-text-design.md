# Клавиши и окружающий текст для программ Linux на телефоне

Дата: 2026-11-28. Статус: пользователь выбрал «разумные решения по умолчанию» (пункт 2 списка
«по очереди»). Решения ниже — мои, записаны, чтобы их было видно.

## Зачем

На телефоне без физической клавиатуры программам Linux не хватает клавиш, которых нет на экранной
клавиатуре Android (Esc, Tab, Ctrl, Alt, стрелки…), а клавиатура Android не видит текста вокруг
курсора в поле программы — автозамена, заглавная в начале предложения и подсказки по контексту не
работают, исправление слова стирает его нажатиями Backspace.

## Что сделать

1. **Строка клавиш над экранной клавиатурой.** Одна строка: ESC, TAB, CTRL, ALT, SHIFT, ←, ↑, ↓,
   →, HOME, END, PGUP, PGDN, DEL. Появляется, пока экранная клавиатура открыта для окна программы
   Linux (Wayland или X11), на месте панели задач (та и так прячется). Для терминала HandTop — нет:
   у него своя панель. С физической клавиатурой экранной нет — нет и строки. В Настройках →
   Экран переключатель «Клавиши над клавиатурой» (включено по умолчанию).
   - CTRL, ALT, SHIFT — залипающие на одно нажатие (как в терминале): действуют на следующую
     клавишу строки или букву с экранной клавиатуры (CTRL + «s» с клавиатуры = Ctrl+S программе).
   - Стрелки, PGUP/PGDN, DEL повторяются, пока держишь.
2. **Окружающий текст** (zwp_text_input_v3, программы Wayland: GTK, Qt).
   - `set_surrounding_text` запоминается (текст, курсор, якорь; байты UTF-8).
   - Клавиатура Android получает текст до и после курсора, выделение, режим заглавных букв.
   - `deleteSurroundingText` — событием `delete_surrounding_text` (байты), а не нажатиями.
   - `setComposingRegion` (клавиатура берёт уже написанное слово в правку) — удаление этого слова
     и тот же текст как preedit в одном `done`.
   - Программа сдвинула курсор или изменила текст — клавиатура узнаёт об этом (`updateSelection`).
   - Подсказки поля: spellcheck → автозамена, sensitive_data → без подсказок.

Не цели: X11-программы получают текст клавишами американской раскладки — их ввод (русский,
подсказки) — отдельная задача. Свои окна HandTop (Files, Настройки) — обычные поля Android.

## Подход

Строка — общий для рабочего стола вид в нижней колонке (между рабочим столом и панелью задач), а
не часть окна: у окон с собственным заголовком (CSD) нет места для кнопки-переключателя, а
изменение размера окна при каждом появлении клавиатуры заставляло бы программу перестраиваться.
Залипшие модификаторы знает сервер Wayland (`KeyLatch`): его читает и строка, и соединение с
клавиатурой. Отвергнуто: строка внутри каждого окна (как у терминала) — см. выше; две строки —
на телефоне с клавиатурой по высоте не остаётся места.

Логика смещений (UTF-8 ↔ символы Java, что удалить, какое слово взять в правку) — в `SurroundingText`
без Android, с тестами.

## Проверка

- Модульные тесты: смещения UTF-8 (кириллица, эмодзи), текст до/после курсора и выделение,
  удаление с обрезкой по краям, область правки, флаги типа поля, залипание модификаторов.
- На телефоне: GNOME Text Editor (GTK 4) — автозамена и заглавные клавиатуры Android, удаление
  слова, CTRL + буква, стрелки и ESC; программа Qt; окно X11 — строка работает, текст как раньше.

## Как вышло (2026-11-28)

Сделано, как описано. Проверено на телефоне (клавиатура Samsung): строка клавиш появляется только
для окна Linux (в поле поиска HandTop — нет); ESC, стрелки, HOME/END, DEL, SHIFT+← (выделение),
CTRL + «a» с клавиатуры (выделить всё), набор поверх выделения — в GNOME Text Editor под Wayland и
под X11. Программа присылает окружающий текст, клавиатура получает положение курсора
(`updateSelection`). Автозамену и подсказки проверить не удалось: на телефоне в клавиатуре
выключен предиктивный ввод (подсказок нет и в обычных полях Android). Строка появляется только с
экранной клавиатурой: с физической (в том числе виртуальной клавиатурой scrcpy) её нет.
