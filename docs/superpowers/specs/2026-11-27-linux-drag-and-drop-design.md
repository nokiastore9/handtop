# Перетаскивание между Files и программами Linux

Дата: 2026-11-27. Статус: схема утверждена пользователем («yes, proceed»); шаги 1–3 сделаны 2026-11-28 (X11 — в тот же день, по списку «по очереди»).

## Зачем

Files уже перетаскивает файлы между своими окнами, в папки и на рабочий стол (5a). Пользователь
хочет, чтобы файлы так же переходили в программы Linux и обратно: бросить документ в редактор,
файл в папку Thunar или Dolphin, вложение в браузер; вытащить файл из файлового менеджера Linux в
Files. Это последний пункт списка «Files v2».

## Что сделать

1. **Files → программы Linux (Wayland).** Окно Linux принимает файлы из Files. Программа
   получает `text/uri-list`: `file:///root/...` для файлов Linux, `file:///sdcard/...` для
   файлов телефона (если есть «Доступ ко всем файлам»). Что сделать с файлами, решает программа.
2. **Программы Linux → Files, другие программы Linux и та же программа.** Перетаскивание,
   начатое программой (`wl_data_device.start_drag`), доходит до любого окна: Files показывает
   своё меню «Переместить / Копировать», окно Linux получает данные прямо от программы-источника.
3. **X11 (XDND)** — мост в `Xwm`, отдельный шаг после Wayland. Окна X11 принимают
   перетаскивания HandTop (из Files, программ Wayland и других окон X11) и начинают свои.

Не цели: перетаскивание из меню и всплывающих окон; файлы Linux на рабочий стол (ярлыки) — потом.

## Подход

Все перетаскивания между окнами идут через системный drag and drop Android (`startDragAndDrop`,
`DragEvent`). Android сам ведёт перетаскивание через окна — пальцем и мышью в DeX, — Files уже
устроен так же. Отвергнуто: вести палец через окна самим (сложнее, разошлось бы с Files).

- **Окно Linux как приёмник.** `WaylandWindowContent` слушает `DragEvent` и переводит их в
  `wl_data_device`: `enter` / `motion` / `leave` / `drop` поверхности под пальцем, с
  `wl_data_offer`, который создаёт HandTop. Действия (v3): источник даёт свои, приёмник —
  `set_actions`; выбор по протоколу: предпочтённое приёмником, если его допускают обе стороны,
  иначе первое общее из copy, move, ask. Бросок засчитывается, если приёмник принял тип
  (`accept`) и действие не none.
- **Программа Linux как источник.** На `start_drag` окно, в котором держат палец (или кнопку
  мыши), запускает `startDragAndDrop` с `LinuxDrag` как `localState`; дальше указатель окна молчит
  до конца перетаскивания (Android отменяет касание; отпускание кнопки программе не шлётся).
  Тень: картинка значка перетаскивания программы, когда она её нарисует, иначе значок файла.
- **Источник ← приёмник.** Приёмник Linux читает данные прямо у источника (`send` с тем же
  каналом, как буфер обмена). Files читает `text/uri-list` сам, переводит пути
  (`LinuxPaths.toAndroid`) и спрашивает «Переместить / Копировать». Источнику Files всегда
  сообщает copy: программа-источник ничего не удаляет, перенос делает Files.
- **Бросок в окно Linux** сначала возвращает окну указатель (`wl_pointer.enter` под пальцем), как
  KWin и Mutter: Qt иначе не открывает меню «копировать / переместить / ссылка» (PCManFM-Qt).
- **Состояние** — сеанс перетаскивания в `WaylandServer` (один за раз); заканчивается на
  `ACTION_DRAG_ENDED`: неудачный бросок — `cancelled` источнику, удачный — `dnd_drop_performed`,
  потом `dnd_finished`, когда приёмник закончил (`finish` или уничтожил offer).

## Проверка

- Модульные тесты: кодирование и разбор `text/uri-list` (пробелы, кириллица, комментарии,
  `file://localhost`, чужие схемы), выбор действия.
- На телефоне: Files → GNOME Text Editor (открывает файл), Files → Thunar (копирует в папку);
  Thunar → Files (меню, копия на месте); Thunar → GNOME Text Editor; программа Qt (PCManFM-Qt)
  в обе стороны; бросок мимо — источник получает отмену.

## X11 (XDND)

- **Окно X11 как приёмник.** Android-перетаскивание над окном X11 переводится в XDND (версия 5,
  не выше версии окна из `XdndAware`; ниже 3 — окно броски не берёт). Источник — окно WM HandTop:
  берёт `XdndSelection`, шлёт `XdndEnter` (типы; больше трёх — `XdndTypeList`), `XdndPosition`
  (корневые координаты, `XdndActionCopy`), `XdndLeave` при уходе, `XdndDrop` при броске, если
  последний `XdndStatus` принял. Данные окно читает по `SelectionRequest`: `TARGETS`,
  `text/uri-list`, `UTF8_STRING` / `text/plain;charset=utf-8`, `text/plain`; от программы Wayland
  — через её `send`. `XdndFinished` — `dnd_finished` источнику Wayland.
- **Программа X11 как источник.** Начиная перетаскивание, программа берёт `XdndSelection`; HandTop
  слышит это через XFixes и сразу читает `TARGETS`, затем `text/uri-list` и текст (до 1 МБ). Пока
  палец в окне, перетаскивание ведёт сама программа (внутри окна и между её окнами). Когда палец
  выходит из окна, HandTop запускает `startDragAndDrop` с `X11Drag` (данные уже прочитаны), а
  программе шлёт Escape (отмена в GTK, Qt, Chromium), уводит указатель далеко за окна и отпускает
  кнопку: иначе программа бросила бы файлы туда, где палец был последним (папка боковой панели —
  перемещение).
- **Окна за экраном.** GTK держит окна 2×2 с override-redirect в (−100, −100); они не меню
  (`X11Sizing.offScreen`), иначе слой меню забирал бы все касания.
- **Проверено на телефоне:** Files → Thunar (X11), Thunar (X11) → Files (меню, копия),
  Thunar (X11) → GNOME Text Editor (Wayland), PCManFM-Qt (Wayland) → Thunar (X11),
  Thunar → Thunar (два окна X11); касания после перетаскивания работают.
